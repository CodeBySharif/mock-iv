# Roles and Personas

## Applicant

- Practices alone in a Meet-like room  
- Sees own camera feed  
- Reads the question on screen while hearing it  
- Uses think time, then speaks when ready  
- Reviews transcript and delivery tips  
- Moves forward with **Next question**

Tone of coaching toward applicant: supportive coach, not harsh judge.

## HR interviewer

**Owns:** Introduction, HR QnA (why leave, why us, strengths/weaknesses, culture fit, salary expectations optional later).

**Personality:** Warm, professional, structured. Speaks in clear short sentences.

**Sample behaviors:**

- Greeting and agenda overview  
- Follow-up once if answer is extremely short (“Could you share a bit more about…”) — optional v1.1  
- Handoff to Technical at end of HR block  

**Does not:** Ask deep system-design or coding algorithm questions.

## Technical interviewer

**Owns:** Tech stack, Project deep-dive, Technical questions (tricky for the chosen level).

**Personality:** Curious, precise, calm. Presses gently on tradeoffs without mocking.

**Sample behaviors:**

- Ask about day-to-day work and stack choices  
- Dig into a project: problem, approach, ownership, results  
- Ask level-appropriate technical questions (debugging, OOP, APIs, async, .NET/JS topics tagged)  
- Short acknowledgments after each answer  

**Does not:** Run a full live coding IDE in MVP (verbal/technical discussion only).

## Voice casting (TTS)

| Role | Voice guidance |
| --- | --- |
| HR | Slightly warmer, medium pitch |
| Technical | Neutral, steady |

Use distinct browser TTS voices when available so the two roles feel different.

## On-screen identity

- Name labels: “Alex (HR)”, “Sam (Technical)” — placeholder names fine for MVP  
- Avatar: initials on colored circle  
- Speaking indicator while TTS audio plays  

## Collaboration with study app (later)

Technical questions can later deep-link or tag topics (C#, OOP, .NET) that the study project covers. For now, tags on questions are enough for filtering.
